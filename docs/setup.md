# Setup and Import Guide

## Status

This is a sanitized development export of the AI-Powered Lead Management System, based on a saved workflow from November 13, 2026. It is shared for portfolio review and learning. It has not been re-tested end-to-end after export and is not production-ready.

**Keep the workflow inactive until the known issues below are resolved and tested.**

## Requirements

- A working n8n instance
- HubSpot private app/service-key credentials with permissions for contacts, deals, and tasks
- OpenAI credentials for the model node
- Gmail credentials if email notifications are enabled
- The HubSpot contact properties listed below

## Import

1. In n8n, open **Workflows** and choose **Import from File**.
2. Select `workflows/ai-powered-lead-management.json`.
3. Keep the workflow inactive while configuring it.
4. Reconnect credentials on every HubSpot, OpenAI, and Gmail node. Credential references were deliberately removed from this public export.

## Notification email

The two Gmail nodes use the placeholder `REPLACE_WITH_YOUR_NOTIFICATION_EMAIL@example.com`. Replace it inside n8n with an address you control. Do not commit a personal address to this repository.

## Expected input

The webhook/subworkflow is intended to receive these fields:

| Field | Description |
|---|---|
| `name` | Full name |
| `email` | Valid email address |
| `phone` | Phone number |
| `company` | Company name |
| `service_needed` | Requested service |
| `budget` | Non-negative number |
| `message` | Lead message |
| `source` | Lead source |

Example synthetic payload:

```json
{
  "name": "Jordan Example",
  "email": "jordan.example@example.com",
  "phone": "+1 202 555 0147",
  "company": "Example Studio",
  "service_needed": "Website redesign",
  "budget": 5000,
  "message": "We need a website redesign this quarter.",
  "source": "portfolio_test"
}
```

Send it as a JSON POST body to the webhook URL generated by n8n. The Execute Workflow trigger receives its defined input fields at the root of the input object.

## HubSpot prerequisites

Confirm these custom contact properties exist:

- `lead_score`
- `lead_priority`
- `ai_reason`
- `recommended_action`
- `ai_lead_status`

Also verify that the configured deal pipeline/stage values exist in your HubSpot portal and that the association type IDs are valid for your account.

## Known issues from static review

The following are findings from inspecting the saved JSON, not live execution results. They have **not** been fixed in this published snapshot:

1. **Validation routing:** both outputs of the `If` validation node connect to the HubSpot contact search. Invalid leads are therefore not stopped by the current graph.
2. **Warm-lead branch:** the true output of `If2` has no downstream node. Leads in the middle score range have no follow-up action connected there.
3. **Contact IDs:** several expressions use `vid` or the initial contact-search response. Verify the actual output from the imported HubSpot node; current HubSpot APIs commonly use `id`. A brand-new contact will not exist in the initial search response.
4. **Webhook input mapping:** `Edit Fields` reads root-level fields. Webhook payload data is commonly nested under `body`, while the subworkflow trigger receives defined fields at the root. Confirm both trigger input shapes.
5. **Duplicate-check branches:** both outputs of `Contact Exists?` converge on the same create-or-update node. This may be intentional because that node upserts the contact, but the condition currently does not alter the path.

## Safe test sequence

1. Use synthetic data only.
2. Fix validation routing and confirm invalid leads stop before CRM writes.
3. Test a new contact, then submit the same email again.
4. Confirm tasks and deals associate using the ID returned by the contact upsert node.
5. Test hot (80–100), warm (50–79), and cold (0–49) scores separately.
6. Verify contact properties, deal/task associations, and Gmail delivery.
7. Activate only after all tests pass.

## Security

Never commit API keys, access tokens, private customer records, personal notification addresses, or production webhook URLs. Store credentials in n8n's credential manager, not in workflow JSON or source control.
